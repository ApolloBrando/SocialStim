# QoL interaction and readability pass

This is a separate PR from the role-bug audit. It changes presentation and input convenience; authoritative role rules and seeded NPC choices remain behind the existing assembly boundaries. Later role renaming and Vigilante rules are separate work.

## Every change and how to use it

1. **Character identity colours.** The attributed speaker name and that participant's living roster name use the same colour. Names mentioned inside sentences keep a shared blue highlight. Colours derive from public seat identity, never hidden or claimed roles. The default seven participants have distinct swatches; the twelve-swatch palette cycles for larger casts. Seat numbers and literal names remain available, so colour is supplementary. Dead roster names remain grey; historical dialogue retains its attribution colour.
2. **Quieter actions.** Choice surfaces, action headings and action tags use neutral contrast instead of competing action-specific text colours. Role badge faction colours remain green/red/orange. Brief situation effects retain their existing accessibility controls.
3. **Underlined actions from the opening statement.** Every tagged statement underlines its action label, including the initial accusation/defense that starts a branch. Native uGUI underline geometry preserves literal text indices and name styling, including with effects disabled.
4. **Explicit reply context.** A separate context line identifies the referenced speaker, action and subject. Agree/Disagree descriptions say which statement will be supported or challenged. Intervening agreements do not become the new accusation. The context stays separate from the action-selection heading.
5. **Direct target selection.** Choose Accuse or Defend, then click a legal participant to perform the action immediately. Night, vote and nomination choices can be made directly from the roster when unambiguous. There is no post-target confirmation. Illegal/dead/self choices remain governed by the validated request. A root discussion roster click cannot guess between accusation and defense.
6. **Remove unwanted context options.** Public record and Mark as a suspect are removed from the UI, along with their target submenu and local marker state. The scoped transcript and portable public-record projection remain available internally for compatibility and regression coverage; they are not menu options.
7. **Seat shortcuts and target focus.** Keys 1–9 select the corresponding legal roster seat. Mouse and native arrow/Enter navigation remain available for every population. Opening a target action focuses the first legal participant; the textual focus marker and roster scrolling make keyboard selection visible. The one-frame guard prevents a submit from also selecting a newly rendered option.
8. **Back and help.** Escape closes role/reference help, closes display options, or cancels a target/action category. F1 opens Roles while gameplay menus are closed. Back remains available as a visible button. New prompts state which action is choosing a target.
9. **0–200% text-speed slider.** A native uGUI slider replaces the cycling speed button. 100% is the existing 84 text elements/second, 200% is 168, and 0% pauses animated reveal. Drag or use arrows; Home/End select the limits. The percentage is displayed. Instant text, Skip and Effects Off retain their existing bypass behavior. An empty line at 0% cannot stall. Changing speed preserves reveal progress and does not acknowledge a gameplay choice.
10. **Usable settings panel and persistence.** The expanded panel fits the slider and its help text. Existing valid preferences are preserved; older speed values clamp to the slider range. Changes apply immediately, but disk persistence is debounced for half a second rather than saving on every drag tick. Pause/quit/destruction flush pending preference writes. Only display preferences persist, never a run.
11. **Read back without losing your place.** Scrolling or dragging away from the latest dialogue stops automatic following. Incoming lines do not pull the transcript to the bottom. Latest dialogue resumes following. Reading back and opening settings/reference menus pause spectator auto-advance; returning to the latest line resumes it.
12. **Role-reference wrapping.** Headings and descriptions explicitly wrap to the panel width, with unrestricted vertical growth in the existing scroll view. Layout minimum width no longer expands a row to fit an entire unwrapped paragraph. The following role-content update supplies the requested consistent description structure and new names.

New wording is editable in Assets/_Project/Data/Dialogue/GameText.json, with validated portable defaults. Existing serialized fields and asset GUIDs are preserved. The colour key now explains identity versus mention colours rather than the removed multi-colour action scheme.

## Research, design decisions and limits

The sources below were checked on 20 October 2026. These are applied design choices, not claims that generic guidelines prove this game's usability or that the game meets a certification standard.

| Primary source | Finding | Application |
| --- | --- | --- |
| [Microsoft XAG 101: Text display](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/101) | Readability includes spacing, contrast and display conditions. | Wrapped role descriptions, stable text surfaces and a visible speed value; native font/layout evaluation remains necessary. |
| [Microsoft XAG 102: Contrast](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102) | Text and controls need contrast across their actual backgrounds. | Separate day/night character swatches; a numeric sRGB check across day/night panels and focus surfaces gives a minimum 5.65:1 for the speaker palette. This is not rendered-frame validation. |
| [Microsoft feature tags: Color alternatives](https://learn.microsoft.com/en-us/gaming/accessibility/accessibility-feature-tags) | Colour alone should not communicate identity or important state. | Keep literal speaker names, seat numbers, action tags, role abbreviations and alive/dead text. Unique colours are an aid, not a replacement. |
| [Microsoft XAG 104: Subtitles/captions](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/104) | Identify who is speaking in text. | Colour only the attributed speaker prefix with their identity colour; mentioned names have a different shared style. |
| [Microsoft XAG 112: UI navigation](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112) | Interaction and navigation should be predictable and work with digital input. | Consistent Back/Escape behavior, visible target instructions, native slider and button navigation, plus optional seat shortcuts. |
| [Microsoft XAG 113: UI focus](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/113) | Focus must be visible and must not disappear onto hidden controls. | Textual focus markers, focus on legal roster entries and a highlighted slider; native playtesting is still required for transitions and small windows. |
| [Nielsen Norman Group: ten usability heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/) | Clear state, recognition, efficient frequent actions and easy exits reduce navigation burden. | Explicit branch context, fewer clicks, direct targets and removable action selection. The user's direct-selection preference takes precedence over adding confirmation dialogs; legality and input guards remain. |
| [Game Accessibility Guidelines: reading pace](https://gameaccessibilityguidelines.com/allow-players-to-progress-through-text-prompts-at-their-own-pace/) | Readers need control of pacing; new chat messages should not force scroll position. | Paused reveal, instant/skip options, manual transcript browsing and an explicit return to the latest dialogue. Spectator playback waits while the player is reading back. |
| [Unity uGUI 2.0 Slider](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/manual/script-Slider.html) | Native range, value, navigation and change events are available. | A real Slider uses an explicit 0–200 range, whole-number percentages and no-notify refresh to prevent recursive setting events. |
| [Unity Input System 1.17 UI support](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.17/manual/UISupport.html) | UI input is handled through the event system and UI input module. | Preserve the existing input module and native Selectable behavior instead of using gameplay state to emulate menus. New convenience shortcuts only run in the appropriate UI context. |
| [Unity Profiler introduction](https://docs.unity3d.com/6000.0/Documentation/Manual/profiler-introduction.html) | Measure actual player/editor performance to locate expensive work. | Avoid per-tick preference saves and rebuild underline geometry only on content/reveal/layout changes. No performance gain is claimed without Unity profiling. |

The general game-development practice is to keep reversible menu state in presentation, validate commands again in the rules layer, retain deterministic seeded decisions, and test the behavior that can regress. Portable tests verify semantic state and transaction behavior; they cannot substitute for native input, layout, rendering or performance tests. Screen narration, remappable bindings, configurable identity colours and a dedicated UI scale are useful future accessibility work and are not claimed as delivered here.

## Verification

Twelve new shared test cases verify speed conversion/validation, 0% pause/resume/skip/instant/empty lines, speaker versus mention attribution, literal/markup preservation, direct legal target choice and original-statement reply resolution. All 246 shared portable tests pass on this standalone QoL branch. Run the Python scaffold/validator tests and NUnit compatibility compilation before publication.

Unity is unavailable. Syntax parsing is not Unity API compilation. Native acceptance checks: all target flows without a confirmation; root discussion click makes no guessed action; 1–9 and arrow/Enter navigation; modal/back focus; action underlines across wrapped and partially revealed tags; speaker/roster colours with effects off; gray dead entries; slider drag/arrows/Home/End/0% recovery and persistence after restart; no disk-save stutter while dragging; long wrapped role descriptions; scrolling back during live dialogue; spectator pause/resume; narrow window layout and multiple DPI scales.
